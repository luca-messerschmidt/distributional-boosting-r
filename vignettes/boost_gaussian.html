Overview

This vignette introduces the main workflow for fitting Gaussian location-scale regression models with component-wise gradient boosting using asp26boost.

Unlike conventional regression models, which typically model only the conditional mean of a response, distributional regression allows several parameters of the response distribution to depend on covariates. For a Gaussian response, this means that both the conditional mean and the conditional standard deviation can be modeled:

\[ Y_i \mid \mathbf{x}_i \sim \mathcal{N}(\mu_i, \sigma_i^2). \]

In asp26boost, the two distributional parameters are represented by separate predictors,

\[ \mu_i = \eta_{\mu,i}, \qquad \log(\sigma_i) = \eta_{\sigma,i}, \]

so that the fitted standard deviation is always positive.

Component-wise boosting estimates these predictors iteratively. At each update, the current negative gradient of the joint Gaussian negative log-likelihood is calculated. Candidate base learners are then fitted to this gradient, and the best candidate is selected. Only the selected learner is added to the corresponding predictor, multiplied by a learning-rate parameter.

This combination of small updates and early stopping provides both regularization and variable selection. Covariates that are never selected remain absent from the corresponding predictor, while selected effects are shrunken toward their initial values.

asp26boost supports:

  • separate predictor matrices for the location and scale submodels;
  • linear, penalized spline, or automatically selected base learners;
  • cyclic and noncyclic parameter-update schedules;
  • fixed stopping iterations;
  • patience-based internal early stopping;
  • cross-validation for selecting the stopping iteration; and
  • grid search over stopping iterations, learning rates, and learner types.

The following sections demonstrate these features using a simulated heteroskedastic Gaussian regression problem.

Simulated Gaussian Location-Scale Data

We begin by generating a dataset in which different predictors affect the conditional mean and conditional scale.

  nrow = n,

The data-generating mechanism contains three signal variables for the location model (x1, x2, x3) and three different signal variables for the scale model (x4, x5, x6). The remaining variables are noise.

The scale model is defined on the logarithmic scale,

\[ \log(\sigma_i) = 0.5x_{i4} -0.4x_{i5} +0.3x_{i6}, \]

which ensures that the resulting standard deviation

\[ \sigma_i = \exp\{\log(\sigma_i)\} \]

is positive.

This setup illustrates an important feature of distributional regression: a predictor can influence the variability of the response without affecting its conditional mean.

Fitting a Gaussian Boosting Model

Gaussian models are fitted using boost_gaussian().

fit <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = 100,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  method = "cyclic"
)

Here:

  • X contains the predictors available for the location model;
  • Z contains the predictors available for the scale model;
  • y is the response;
  • mstop controls the maximum number of boosting iterations;
  • nu_mu is the learning rate for the location predictor;
  • nu_sigma is the learning rate for the scale predictor; and
  • method determines how the two distributional parameters are updated.

Using the same matrix for X and Z is not required. Different predictor sets can be supplied when different variables are considered relevant for the two distributional parameters.

For example, one could use

fit <- boost_gaussian(
  X = X[, c("x1", "x2", "x3", "x7")],
  Z = X[, c("x4", "x5", "x6")],
  y = y
)

to restrict the candidate variables available to each submodel.

The Gaussian Loss

The model is fitted by minimizing the joint Gaussian negative log-likelihood. Apart from the constant \(n\log(2\pi)/2\), the empirical risk is

\[ R(\boldsymbol{\mu},\boldsymbol{\sigma}) = \sum_{i=1}^n \left[ \log(\sigma_i) + \frac{(y_i-\mu_i)^2} {2\sigma_i^2} \right]. \]

Consequently, the location and scale predictors are not fitted independently. The gradient for one parameter depends on the current estimate of the other parameter.

For the Gaussian family, the negative gradients with respect to the location and scale predictors are

\[ u_{\mu,i} = \frac{y_i-\mu_i}{\sigma_i^2}, \]

and

\[ u_{\sigma,i} = \frac{(y_i-\mu_i)^2}{\sigma_i^2}-1, \]

respectively.

The boosting algorithm fits candidate base learners to these working responses and updates the selected predictor in small steps.

Base Learners

The argument learner determines which candidate base learners are considered during boosting.

Linear Base Learners

With

learner = "linear"

each candidate corresponds to a linear effect of one predictor.

This is appropriate when the relationship between a predictor and the distributional parameter is expected to be approximately linear.

For example:

fit_linear <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = 100,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  learner = "linear"
)

Penalized Spline Base Learners

Nonlinear relationships can be represented using penalized B-spline base learners:

fit_spline <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = 100,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  learner = "spline"
)

For each covariate, a cubic B-spline basis is constructed and a difference penalty controls the roughness of the fitted effect.

The spline candidates are calibrated to a common target of four effective degrees of freedom. This makes spline candidates comparable with each other during component-wise selection.

Spline learners are particularly useful when the effect of a predictor is not expected to be well described by a straight line.

Automatic Learner Selection

The setting

learner = "auto"

allows both linear and spline candidates to compete during boosting.

fit_auto <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = 100,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  learner = "auto"
)

At each update, the candidate with the best fit to the current working gradient is selected.

"auto" is therefore useful when the functional form of an effect is unknown. If interpretability and a strictly linear model are desired, "linear" is preferable. If nonlinear effects are expected, "spline" provides a more flexible alternative.

Cyclic and Noncyclic Updating

Because the Gaussian model contains two distributional parameters, the algorithm must determine which parameter to update at each boosting step.

asp26boost provides two update schedules.

Cyclic Updating

Under the cyclic schedule, the location and scale predictors are updated successively in a fixed order.

fit_cyclic <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = 100,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  method = "cyclic"
)

Within one cyclic round, each active distributional parameter receives one update. The gradient is recalculated before each update, meaning that the scale update uses the location estimate produced immediately beforehand.

For cyclic boosting, separate stopping budgets can be supplied for the location and scale predictors.

fit_cyclic <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = c(mu = 100, sigma = 50),
  nu_mu = 0.05,
  nu_sigma = 0.05,
  method = "cyclic"
)

This allows the two distributional parameters to have different model complexities.

Noncyclic Updating

With

method = "noncyclic"

the algorithm considers the best candidate update for each distributional parameter and applies only the candidate that produces the greatest reduction in the joint empirical risk.

fit_noncyclic <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = 100,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  method = "noncyclic"
)

Thus, each noncyclic boosting iteration performs exactly one parameter update. The stopping iteration is shared across the complete model.

The two approaches use the same gradients and base learners. They differ only in how candidate updates are allocated between the distributional parameters.

Boosting Paths and Variable Selection

One of the main advantages of component-wise boosting is that the boosting path provides information about variable selection.

The coefficient trajectories can be visualized using

plot(
  fit,
  type = "path",
  submodel = "mu",
  top_n = 8,
  scale = "original"
)

and for the scale predictor:

plot(
  fit,
  type = "path",
  submodel = "sigma",
  top_n = 8,
  scale = "original"
)

The plots show how the estimated effects evolve as boosting progresses.

The scale argument controls whether effects are displayed on the standardized training scale or transformed back to the original predictor scale.

Selection frequencies can be visualized with

plot(
  fit,
  type = "frequency",
  submodel = "mu",
  top_n = 8
)

and

plot(
  fit,
  type = "frequency",
  submodel = "sigma",
  top_n = 8
)

The selection frequency records how often a predictor has been selected during the boosting procedure. Predictors selected frequently are therefore favored by the component-wise fitting procedure.

This is particularly useful for models with many candidate predictors: early stopping can prevent weak variables from entering the model at all, while repeatedly selected variables accumulate larger effects.

The plotting methods require the boosting path to be retained, which is the default behavior.

Early Stopping

The stopping iteration is the main regularization parameter in component-wise boosting.

A small number of iterations produces a strongly regularized model. As more iterations are added, additional effects can enter the model and previously selected effects can be refined.

Simply choosing a large mstop based on training performance is generally not appropriate because training negative log-likelihood tends to improve as the model becomes more complex.

Instead, the stopping iteration should ideally be selected using out-of-sample predictive performance.

Patience-Based Early Stopping

asp26boost provides an internal validation-based early-stopping mechanism through the patience argument.

For example:

fit_es <- boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  mstop = 1000,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  patience = 25,
  validation_split = 0.2
)

Here, 20% of the training observations are used as a validation sample. Boosting continues while validation risk improves. If the validation risk does not improve for 25 consecutive iterations, the search is stopped.

The best stopping point is subsequently used to refit the model on the complete dataset.

This separates the search for the stopping iteration from the final model fit: the final model uses all available observations rather than only the training portion of the early-stopping split.

patience is therefore useful when an automatically determined stopping iteration is desired without explicitly specifying a cross-validation procedure.

Cross-Validation

An alternative is to select the stopping iteration using \(k\)-fold cross-validation.

cv_boost_gaussian() evaluates the predictive negative log-likelihood over a sequence of boosting iterations.

cv_fit <- cv_boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  k = 5,
  mstop = 500,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  method = "cyclic",
  learner = "linear",
  seed = 27092001
)

For a Gaussian model, the validation criterion is the mean negative log-likelihood

\[ \hat{\rho}_v(m) = \frac{1}{n_v} \sum_{i \in v} \left[ \log(\hat{\sigma}_i^{(m)}) + \frac{(y_i-\hat{\mu}_i^{(m)})^2} {2(\hat{\sigma}_i^{(m)})^2} \right]. \]

Lower values indicate better predictive performance.

The cross-validation procedure fits the complete boosting path for each fold. The resulting path can therefore be evaluated at every stopping iteration up to the supplied maximum.

Visualizing the Cross-Validation Curve

The cross-validation results can be visualized directly:

plot(cv_fit)

The curve shows the estimated validation negative log-likelihood as a function of the boosting iteration.

The selected stopping iteration corresponds to the minimum of the estimated validation risk.

This visualization is useful for diagnosing the regularization behavior of the model. Typically, validation risk initially decreases as useful effects are added and eventually levels off or increases as additional complexity begins to hurt predictive performance.

Hyperparameter Grid Search

In addition to the stopping iteration, the learning rates and base-learner type can be treated as tuning parameters.

cv_boost_grid() evaluates combinations of the supplied candidate values.

grid_fit <- cv_boost_grid(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = sample_data$y,
  k = 5,
  mstop_grid = c(50, 100, 200),
  nu_mu_grid = c(0.01, 0.05, 0.1),
  nu_sigma_grid = c(0.01, 0.05, 0.1),
  seed = 27092001
)

The grid search evaluates the Cartesian product of the supplied candidate hyperparameters. Consequently, the computational cost can increase substantially when many candidate values are supplied.

For practical applications, it is therefore advisable to first choose a reasonable range of learning rates and then use cross-validation to identify a suitable combination.

Choosing a Model Configuration

The main modeling choices can be summarized as follows.

Goal Recommended configuration
Approximately linear effects learner = "linear"
Nonlinear effects expected learner = "spline"
Functional form unknown learner = "auto"
Standard distributional boosting method = "cyclic"
Select one best parameter update at a time method = "noncyclic"
Fast automatic stopping patience
More robust stopping selection cv_boost_gaussian()
Tune several hyperparameters cv_boost_grid()

For most applications, a sensible starting point is a cyclic model with a relatively small learning rate and cross-validation-based stopping.

For example:

fit <- cv_boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = y,
  k = 5,
  mstop = 500,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  method = "cyclic",
  learner = "linear",
  seed = 123
)

If nonlinear effects are plausible, replacing learner = "linear" by learner = "spline" is a natural extension.

Reproducibility

Functions involving random resampling accept an explicit seed argument. Providing a seed makes the fold assignment or validation split reproducible on the same R and package versions.

For example:

cv_fit <- cv_boost_gaussian(
  X = sample_data[, -1],
  Z = sample_data[, -1],
  y = y,
  k = 5,
  mstop = 500,
  nu_mu = 0.05,
  nu_sigma = 0.05,
  seed = 27092001
)

For fully reproducible analyses, the R version and package version should also be recorded.

Summary

This vignette demonstrated the main workflow for Gaussian component-wise boosting with asp26boost.

The key steps are:

  1. construct predictor matrices for the location and scale submodels;
  2. fit a Gaussian location-scale boosting model with boost_gaussian();
  3. choose between linear and spline base learners;
  4. choose a cyclic or noncyclic update schedule;
  5. inspect coefficient paths and variable-selection frequencies;
  6. control model complexity through early stopping;
  7. use cross-validation to select the stopping iteration; and
  8. optionally use cv_boost_grid() to tune several hyperparameters.

The central feature of the approach is that the conditional distribution is modeled jointly. Both the location and scale can depend on covariates, while component-wise updates and early stopping provide regularization and implicit variable selection.

For applications with many candidate predictors, this combination makes component-wise boosting particularly attractive: the algorithm can construct sparse distributional models without requiring an unregularized estimation of all coefficients simultaneously.
